# Project Context & Implementation Plan: Student CRUD Application

## 1. Overview
This project aims to build a modern, responsive Single Page Application (SPA) using **Vite + React (JavaScript)** that interfaces with the existing Spring Boot Student REST API.

---

## 2. Existing Backend Analysis

- **Framework**: Spring Boot 3+ (Java 21 / Maven)
- **Database**: PostgreSQL (`db_student` at `localhost:5432`)
- **Default Port**: `8080`
- **Controller**: `com.sicat.student.StudentController` at `/sicat/students`

### Entity Schema (`Student`)
| Field | Type | Required | Description |
|---|---|---|---|
| `id` | `Integer` | Auto | Primary Key (generated by backend) |
| `firstname` | `String` | Yes | Student's first name |
| `lastname` | `String` | Yes | Student's last name |
| `course` | `String` | Yes | Enrolled program / course (e.g. BSCS, BSIT) |
| `section` | `String` | Yes | Student's section (e.g. 3A, 4B) |

### REST Endpoints
| HTTP Method | Endpoint | Request Body | Response | Description |
|---|---|---|---|---|
| `GET` | `/sicat/students` | None | `200 OK` (Array of `Student`) | Fetch list of all students |
| `GET` | `/sicat/students/{id}` | None | `200 OK` (`Student`) / `404 Not Found` | Fetch single student by ID |
| `POST` | `/sicat/students` | `{ firstname, lastname, course, section }` | `201 Created` (`Student`) | Create a new student record |
| `PUT` | `/sicat/students/{id}` | `{ firstname, lastname, course, section }` | `200 OK` (`Student`) / `404 Not Found` | Update an existing student |
| `DELETE` | `/sicat/students/{id}` | None | `200 OK` (String) / `404 Not Found` | Delete student by ID |

> **CORS / Network Note:** The backend currently does not have `@CrossOrigin` annotations. The React frontend will use Vite's built-in development proxy (`/sicat` -> `http://localhost:8080`) to bypass CORS during development, with an option to add CORS configuration to the Spring Boot controller if required.

---

## 3. Frontend Technology Stack

- **Tooling**: Vite (latest)
- **Framework**: React 19 (JavaScript / JSX)
- **Styling**: Tailwind CSS
- **Design Philosophy**: Non-modal layout. Form is an inline / side-by-side or collapsible card panel (seamless Add / Edit experience without dialog overlays). Inline confirmation for delete actions.
- **Icons**: Lucide React icons
- **HTTP Client**: Native `fetch` with centralized API service wrapper
- **Node & NPM Execution**: System runs Windows with PowerShell script execution restrictions. All commands must be invoked via `cmd /c` or `.cmd`.

## 5. Implementation Roadmap (Phases)

### Phase 1: Project Initialization & Configuration
1. Initialize Vite React JavaScript template inside `student-frontend`:
   `cmd /c "npm create vite@latest student-frontend -- --template react"`
2. Install frontend dependencies (`lucide-react` for icons).
3. Configure `vite.config.js` with a reverse proxy targetting `http://localhost:8080` for `/sicat` endpoints to avoid CORS restrictions.

### Phase 2: API Integration Layer
1. Create `studentService.js` handling:
   - `getStudents()`: Retrieves all students
   - `getStudentById(id)`: Fetches individual student
   - `createStudent(payload)`: Sends POST request with `{ firstname, lastname, course, section }`
   - `updateStudent(id, payload)`: Sends PUT request
   - `deleteStudent(id)`: Sends DELETE request
2. Add robust error handling and HTTP status code normalization.

### Phase 3: UI Component Development
1. **Header & Navigation**: Clean top bar with brand title and quick action button (+ Add Student).
2. **Dashboard Metrics (Stats)**: Cards showing total students, unique courses, etc.
3. **Student Table**:
   - Clean column layout: ID, First Name, Last Name, Course (styled badge), Section, Actions (Edit, Delete).
   - Empty state illustration when no students are registered.
   - Loading skeleton / spinner during fetch.
4. **Search & Filter**: Real-time client-side filter by name, course, or section.
5. **Student Form Modal (Add & Edit)**:
   - Dual-purpose modal (Create mode vs Edit mode).
   - Form input validation (prevent empty strings or whitespace-only submissions).
   - Clean error feedback for individual fields.
6. **Confirmation Modal**: Safe deletion prompt confirming student removal before triggering DELETE.
7. **Toast Alerts**: Non-intrusive notification popups for successful actions and error messages.

### Phase 4: Testing & Verification
1. Verify Spring Boot backend connectivity and database persistence.
2. Test full CRUD lifecycle:
   - **Create**: Add multiple students across different courses.
   - **Read**: Verify list rendering, search filtering, and individual view.
   - **Update**: Edit firstname, lastname, course, or section; check updated UI and database sync.
   - **Delete**: Remove student and ensure list updates cleanly.
3. Validate edge cases (network failure, empty data, invalid input).
